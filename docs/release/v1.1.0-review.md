# v1.1.0 candidate review

Reviewed on 2026-09-06, starting from `d7866ea` on `v1.1.0-candidate`.
[PR #3](https://github.com/justinGrosvenor/s3ui/pull/3) had no review comments;
GitHub had no open issues. This pass concentrates on multipart correctness,
the Qt event loop, queue hot paths, and release packaging.

This report records the local review before publication. The release version is 1.1.0.

| Finding | Change and evidence |
| --- | --- |
| Multipart resume trusted incomplete local part records and stale completed parts | Rebuild all expected records from the server's part numbers, sizes, and ETags. Tests cover missing records, missing or short remote parts, and a server accepting a part before its response is lost. |
| Changed source files could be mixed with previously uploaded bytes | Persist size and nanosecond modification time. Restart changed or legacy sessions; fail if the source changes during a running upload. An integration test closes/reopens SQLite between workers and verifies every resulting byte through Moto. |
| Expired multipart sessions could not recover | Restart only on `NoSuchUpload`; permission errors remain failures. |
| Stop requests during the last part could still publish the object | Check pause/cancel immediately before completion; keep complete-but-paused parts resumable. Cancelled paused uploads are aborted in the background without requiring reconnect. |
| Large parts were allocated in memory in full | Stream bounded file parts through botocore and rewind before retries. Part sizing also enforces the 10,000-part ceiling at multi-terabyte sizes. |
| Resumed downloads could combine different object versions | Persist the source ETag and use conditional GETs. Discard stale partial files, validate each range's length, close streaming bodies, and replace the destination only after successful validation. |
| Windows could not replace an existing download destination | Use atomic `Path.replace()`; keep the original destination intact on failures and cancellation. Reject simultaneous downloads to a reserved destination and symlink paths escaping the chosen directory. |
| Resume/retry after switching profiles could target the wrong bucket | Check bucket/profile identity at every engine entry point and keep original engines for paused and active work. Pause All spans the session's engines. Explicitly paused transfers stay paused on restore. |
| Old listings and operation callbacks could update another bucket | Invalidate request generations on navigation and connection changes; ignore stale results and callbacks from another client/bucket. Stale revalidation cannot resurrect deleted objects. Overwrites update a single row. |
| Automatic orphan cleanup could abort another application's uploads | Only retry aborts for cancelled sessions recorded by this application in the selected bucket/profile. Unknown sessions are untouched. |
| Large server-side copies failed or lost metadata | Use managed multipart copy, explicitly carrying source metadata and content headers. A multipart-copy test verifies contents, custom metadata, and content type. |
| Permission errors were treated as free destination names | Only a recognized not-found response means a destination is available. |
| Folder creation and recursive upload discovery blocked the GUI | Run network/filesystem discovery in workers. Persist upload queue entries in batches of 50 and admit work within engine capacity. |
| Queue bookkeeping performed unnecessary work | Prepare all part records in one transaction; commit part completion and progress together. Index bounded queue selection. Bulk pause/resume uses one update per bucket. Coalesce header updates and stop idle progress timers. |
| Shutdown could destroy workers after a two-second timeout | Defer closing while requests finish and continue dispatching Qt events. Track fetch/background threads, stop pending startup callbacks, and defer closing scans and credential tests until their threads finish. |
| Tests suppressed Qt events, garbage collection, filesystem watching, and normal interpreter exit | Remove these workarounds. Tests use explicit connection setup and run with real Qt lifecycle and filesystem models. |
| Bucket scans wrote columns absent from the database | Write the existing snapshot schema, scoped by bucket ID, and update same-day snapshots. |
| Windows/Linux build inputs were absent from version control | Exempt the existing NSIS installer, desktop entry, and AppImage script from ignore rules so they are included in this candidate's changes. CI now checks candidate pushes, Python 3.14, audit-script lint, and distribution builds. |

## Local measurements

Run `python scripts/audit_hot_paths.py` to reproduce the audit with temporary
files and SQLite, without credentials or network access. Raw results are in
[hot-path-results.json](hot-path-results.json).

| Workload | Before | After |
| --- | --- | --- |
| Prepare 10,000 part records | 525.2 ms; 10,000 commits | 29.4 ms; 1 commit |
| Read/hash a 64 MiB part, peak traced Python memory | 64.0 MiB | 2.13 MiB |
| Read/hash the same part, local elapsed time | 27.8 ms | 25.7 ms |

The byte hashes match. These are single local measurements on Apple Silicon,
macOS 26.5.2 and Python 3.14.0, with tracing enabled. They measure local
bookkeeping and buffering, not S3 throughput or total process RSS. Parts within
one upload remain sequential; file-level workers provide concurrency.

Event-loop regression tests use blocked worker requests and timer heartbeats
to verify that folder creation and deferred shutdown continue dispatching GUI
events. Upload discovery is verified to run outside the GUI thread in batches
of at most 50 records.

## Release acceptance still requiring external environments

These checks have not been performed against this working-tree revision:

- Run multi-gigabyte transfers against AWS S3 and the intended compatible service
  (such as MinIO or R2), including network loss, restart, and credential expiration.
- Run the updated CI matrix on Linux, macOS, and Windows; install and interact with
  the resulting Windows installer and Linux AppImage.
- Exercise native first-run setup, platform keychains, drag/drop, and signed/notarized
  distribution on target machines.

A stop request waits for the current S3 request to return; the GUI stays
responsive while shutdown is deferred. Local source-change detection uses size
and modification time, so it is not a full-file cryptographic identity check.

The API choices follow [conditional GET semantics](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/get_object.html),
[Boto3 managed copy](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/copy.html),
and [Python's replacement semantics](https://docs.python.org/3/library/pathlib.html#pathlib.Path.replace).
